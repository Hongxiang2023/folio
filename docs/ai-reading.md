# Paper chat: implementation and review

Goal: let readers summarize and discuss a saved paper without leaving the reading window. Scope: per-PDF text-grounded chat, initial summary on enabling, selectable excerpt, optional cached page/equation images, clickable page citations, local conversation persistence, ChatGPT account sign-in on macOS and OpenAI/Claude API keys. No automatic bulk-library upload, web search, editing files, or remote Folio account.

## User flow

Read PDF → Reading view → Ask this paper → Connection. Choose a provider and save it. For ChatGPT, start sign-in, follow the secure browser link, then Check connection. This uses an installed Codex/ChatGPT runtime; macOS is currently required for the OS sandbox. API connections work with a user-supplied key and model ID. Then choose Enable AI & summarize this paper. Enabling grants permission for that PDF and provider; changing providers requires enabling again. No summary or question is sent merely by opening a paper or connecting an account.

Summaries run once, are saved, and can be retried after failure. Follow-up context is bounded and includes selected excerpts, recent messages, metadata, and optional available images. For long papers, a summary includes a bounded allocation from every extracted page and is labeled incomplete. Page links indicate supplied pages, not an independent verification that the model's claim is supported. There is no external retrieval. Display equations can be sent as original crops when the reader selects images for that page. Text-only answers cannot reliably interpret missing visuals.

Follow-ups use local word-based passage search with neighboring context. Focused questions have a 12,000-character source-text budget, broad questions (for example limitations or comparisons) 24,000; the one-time summary keeps its 90,000-character budget. Broad or unmatched questions distribute an allocation across pages. Short or referential follow-ups use the previous user question and modest support from the prior answer's cited pages. Prior model answers are never treated as paper evidence. Relevant passages can still be missed by lexical search; incomplete context is disclosed and the assistant is instructed to admit missing evidence.

Selected text and figure legends reserve space within the source budget. Explicit selections are preserved even if their combined size exceeds it (up to 10,000 characters of selected text plus 15,000 of legend). Metadata, page labels, the new question, and images are additional. These are character limits, not exact token counts or guaranteed billing savings. History sends only the two latest exchanges, capped at 5,800 characters with explicit shortening markers; full conversations remain saved locally. Context selection and shortening make no extra model calls and introduce no external service. This replaces the former 55,000-character follow-up source budget and twelve unbounded recent messages.

## Privacy and credential review

The loopback server checks its Host, Origin and session/bearer boundary. Connector extensions cannot access AI endpoints even when paired. AI settings never return API keys. API requests use fixed provider HTTPS addresses and reject redirects. Provider errors are sanitized. Electron safeStorage encrypts API keys; if secure OS storage is unavailable, keys remain in memory only. Linux basic_text is treated as unavailable. Keys are never written into source exports or full library backups.

Codex runs with its own HOME, CODEX_HOME, temporary directory, account login, empty workspace, and ephemeral conversations. It cannot inherit the user's ordinary Codex account/configuration. macOS sandbox rules deny unrelated file data reads, writes outside its own directory, and execution of other programs. Tool-related features are disabled, approvals rejected, and unexpected tool items terminate the runtime. The provider runtime manages its own isolated login tokens; API key encryption does not imply those runtime tokens use Electron encryption. Unsupported platforms fail closed for account chat and retain API support.

Paper content is sent only after per-provider consent. API usage is billed to the user's provider account; account sign-in consumes that account's limits. Answers require internet; existing summaries/chat remain local. No live paid request or user-account authentication is part of automated tests. Users complete sign-in or key setup themselves.

Conversations are private JSON files in paper-chat/, remain when reading cache is removed, and are included in full backups. Connection settings and isolated runtime credentials are excluded. Clearing a conversation also disables its consent. Existing local conversation history may be sent to a newly chosen provider only after the user enables that provider for the paper.

## Acceptance and verification

Equation selection labels count detected equations continuously across the paper. They are reading-view identifiers, not extracted publisher equation numbers. The UI and chat context use the same numbering, while stored page/index selection IDs remain unchanged; existing reading caches need no regeneration. Regression coverage includes five equations on separate pages, pages without equations, and multiple equations on one page.

Reading layout version 8 improves equation extraction using complete prose baselines, including short colon-terminated sentence endings, as crop boundaries. Equals signs in long or single PDF text runs are supported; vertical glyph grouping separates distinct displays while retaining multiline expressions, subscripts, and fraction limits. Stacked Greek-symbol fractions without equals signs are also detected. Existing version 7 caches need regeneration to receive these improved crops. Inline reading captions and the chat selector both use continuous document-order numbering.

Local visual QA against the 49-page spatial-ecotypes example found 11 display-equation blocks: one each on pages 16 and 18, five on page 21, two on page 22, and one each on pages 23 and 24. Page 22's upper equation is recovered and its lower sum excludes preceding prose. The complete parsing pipeline was run against the PDF; these counts are validation for this example, not a guarantee of exhaustive equation recognition in arbitrary layouts. Tests cover long text runs, short prose boundaries, separate and multiline displays, fractions, and inline inequalities. Packaged desktop builds must be rebuilt as well as the web assets before a running desktop app can receive the change.

Tests cover consent denial before transmission, one-time summary generation, persistence across restart, provider-switch consent, API-key secrecy, safe image inputs, context bounds, parallel-request rejection, cancellation, local route authorization, connector exclusion, credential-free backups, provider transport shape, and macOS filesystem/symlink isolation. Production TypeScript/Vite build is required. Authentication and live model responses require the user's provider account and are reported separately from mocked integration tests.

This is a local implementation, not an external release. Folio stays free; optional provider service charges are borne by the user.
